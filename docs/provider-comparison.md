# Provider comparison

Generated by `python api/scripts/compare_providers.py --a offline --b gemini`.

Only the generation backend differs between runs. Corpus, retrieval, chunking,
ranking and the golden set are identical, so a difference in the answer metrics
is attributable to the generator rather than to the pipeline around it.

## What was compared

| | |
|---|---|
| Dataset | `eval/golden/smoke.jsonl` — 8 items, 6 answerable, 2 deliberately unanswerable |
| Corpus | 5 semantically indexed chunks (`bge-m3`), 667 chunks total |
| Baseline (`offline`) | Extractive — returns the retrieved passages with no model call |
| Candidate (`gemini`) | `gemini-3.8-flash`, judged by `gemini-3.5-flash` |
| Retrieval | Hybrid BM25 + dense, RRF k=60, lexical reranker, floors 0.25 / 0.50 |

**`anthropic` was not run.** Only `GEMINI_API_KEY` was configured; adding
`ANTHROPIC_API_KEY` enables `--a anthropic --b gemini`.

| Context Recall | 1.000 | 1.000 | +0.000 | [+0.000, +0.000] | no significant change *(control)* |
| Answer Relevancy | 0.467 | 0.733 | **+0.266** | [+0.203, +0.317] | **significant** |
| Answer Relevancy *(run 2)* | 0.470 | 0.783 | **+0.316** | [+0.305, +0.325] | **significant** |

| Faithfulness | not measured | 1.000 *(n=3)* | — | — | not pairable |
| Refusal accuracy | 1.000 | 1.000 | — | — | both correct, 2 items |

Cost for a full 8-item run on `gemini-3.8-flash`: **$0.0006 – $0.0010**.
Latency p50 ranged 568 ms – 6.6 s across runs, which on a sample this small is
noise rather than a measurement.

## Reading this honestly

**The retrieval control held exactly.** Context Precision and Recall moved by
0.000 between runs, confirming only the generator differed. If those had moved,
the generation rows would be meaningless — the script flags that case as
`CONTROL MOVED`.

**Answer Relevancy is the one real finding.** Gemini beat the extractive
baseline by +0.24 to +0.32 across three runs, every interval comfortably clear
of zero and consistent in direction. That is what it should show: the baseline
returns retrieved text verbatim, so it scores poorly on *addressing the question
asked* even when the right passage was retrieved. It measures the value of
generation, not of retrieval.

**Faithfulness is not a comparison.** The offline baseline cannot judge
entailment at all, so there is nothing to pair against. Gemini scored 1.000, but
on only 3 of 6 answerable items, and judged by a model from its own family —
`gemini-3.5-flash` grading `gemini-3.8-flash`. Same-vendor judging reduces
self-preference bias without removing it. Treat it as a smoke test that
verification runs, not as a quality measurement.

**Refusal accuracy is uninformative here.** Both scored 1.000, but the refusal
happens in retrieval — nothing clears the score floors, so no evidence reaches
the generator. Both providers refuse for the same reason, which is a property of
the pipeline rather than of either model.

**The sample is far too small.** Six answerable items over 5 coarse chunks. The
confidence intervals describe variation within that tiny set, not a general
claim about either provider. Context Precision at 0.972 is the only retrieval
metric showing any separation at all.

## What the run surfaced

Running this found four defects that unit tests had not:

1. **The verifier independence guard was nominal.** It compared config strings
   (`claude-opus-5` vs `claude-sonnet-5`) while the Gemini provider ignored the
   requested model entirely — so Gemini would have graded its own output with
   the check still reporting a pass. Providers now declare their own judge
   model and the guard checks what will actually run.
2. **Verification never ran during eval.** The 20% cost-saving sampling gate
   still applied, despite a comment claiming otherwise, making faithfulness a
   measurement of a random subset. `force_verify` now bypasses it for eval runs.
3. **Offline runs were charged for tokens.** Synthetic usage counts were priced
   against a real model, inventing $0.0265 of spend that never happened.
4. **Rate-limited items looked like valid empty answers.** A 429 produced an
   empty answer with no error recorded, so a quota failure was indistinguishable
   from a model with nothing to say. Generation failures are now recorded as
   item errors, and a degraded run is flagged in the report header.

## Reproducing

```bash
# .env at the repository root — never committed
GEMINI_API_KEY=...
ANTHROPIC_API_KEY=...        # optional, enables --a anthropic

cd api
python scripts/compare_providers.py --a offline --b gemini
python scripts/compare_providers.py --a anthropic --b gemini
```

The free Gemini tier exhausts after a few full runs; a 429 shows up as failed
items with a warning in the header rather than as quietly missing numbers.
